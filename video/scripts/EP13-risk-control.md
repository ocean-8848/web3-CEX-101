**画面标题**：风控：交易所的安检系统

## 场景 3：四层风控

**画面标题**：四类风险，对应四层风控

**[3.0]** 交易所同时面对四类风险，每类对应一层风控。第一层是交易前。它防余额不足下单、胖手指错价，还有请求洪水。

> 画面：PRE-TRADE · 同步交易前余额不足胖手指错价请求洪水

**[3.1]** 第二层是交易中，也叫市场监察。它找自成交、刷量、幌骗和拉盘砸盘。

> 画面：IN-TRADE · 异步交易中自成交刷量 幌骗拉盘砸盘

**[3.2]** 第三层是资金，主要是提币。它防盗号提币、洗钱，以及向制裁地址转账。

> 画面：FUNDS · 同步资金盗号提币洗钱制裁地址

**[3.3]** 第四层是账户。它防撞库登录、SIM卡劫持，以及钓鱼之后改密码。

> 画面：ACCOUNT账户撞库登录SIM 卡劫持钓鱼后改密

**[3.4]** 注意，风控不等于拒绝。风控有五种动作：通过、拒绝、限制、加验证、转人工审核。比如降额度，就是一种限制。

> 画面：五种动作：通过拒绝限制加验证转人工

**[3.5]** 风控的目标有三个：减少资金损失，满足合规，降低正常用户的摩擦。第三条和前两条互相冲突。风控所有的难点，都来自这个冲突。

## 场景 5：价格保护带

**画面标题**：价格保护带：拦住胖手指（逐步动画）

**[5.0]** 价格保护带怎么算？举个示例。参考价是50000 USDT，上限是5%。买单价格高于参考价的1.05倍，也就是52500，系统就拒绝。

**[5.1]** 一笔买单报价52000，偏离4%，在带内，系统通过。

**[5.2]** 再来一笔买单，报价60000，偏离20%，系统直接拒绝。手滑填错的价格，根本进不了撮合。这就是防胖手指。

**[5.3]** 注意参考价从哪里来。根据币安公开资料，现货用一段时间的加权平均价做参考价。相关过滤器在 exchangeInfo 接口里下发，具体倍数以接口返回为准。

> 画面：币安现货过滤器：PERCENT_PRICE · PERCENT_PRICE_BY_SIDE由 exchangeInfo 下发 · 参考价参数…

**[5.4]** 为什么不用最新成交价？看这根线。一笔小单就能把最新价打到58000。如果拿它当参考价，保护带会跟着被拉歪。平均价几乎不动。合约里的标记价格，用的也是这个思路。

## 场景 6：交易中风控

**画面标题**：交易中风控：市场监察找四类行为

**[6.0]** 第二层，交易中风控，也叫市场监察。它找四类行为。自成交，是同一用户的买单和卖单互相成交。刷量，是关联账户之间对敲，制造虚假成交量。

> 画面：自成交同一用户的买单和卖单互相成交双方用户 ID 相同 ｜ 刷量关联账户对敲，制造虚假成交量设备、IP、资金来源关联

**[6.1]** 幌骗，是挂大单制造假象，快成交时撤单。拉盘砸盘，是在低流动性的币上集中拉高，然后抛售。

> 画面：幌骗挂大单制造假象，成交前撤单大额挂单撤单率极高 ｜ 拉盘砸盘低流动性币种集中拉高后抛售短时涨幅异常，资金集中流入

**[6.2]** 自成交有同步解法，叫自成交预防，简称 STP。根据币安公开资料，下单时可以指定 STP 模式。撮合引擎发现两边是同一账户，就让一边或两边订单失效。

> 画面：自成交预防 STP · 同步selfTradePreventionModeEXPIRE_TAKER · EXPIRE_MAKER · EXP…

**[6.3]** 刷量和幌骗没有同步解法。系统必须看一段时间的行为才能判断。所以它们属于异步风控，事后发现，再送进案件系统。

> 画面：刷量 · 幌骗 · 异步看一段时间的行为才能判断事后发现 → 案件系统

## 场景 7：提币与账户风控

**画面标题**：盗号者的四步路径，风控步步设卡（逐步动画）

**[7.0]** 第三层和第四层要放在一起看。盗号者拿到密码以后，典型路径有四步。登录，改2FA或邮箱，加新提币地址，然后提走全部余额。

**[7.1]** 账户风控在第一步设卡。新设备、机房 IP、异地 IP，都是信号。但正常用户也会换手机。所以账户风控输出风险分，不是是或否。

> 画面：新设备指纹机房 IP · 异地 IP输出风险分

**[7.2]** 第二步改安全设置，会触发冷却期。根据币安公开资料，修改安全设置后会暂停提币24小时，具体时长以官网为准。

> 画面：改安全设置后暂停提币 24 小时时长以官网为准

**[7.3]** 第三步加新地址。首次向一个地址提币，系统可以加验证，或者延迟处理。提币地址白名单也是在防这一步。

> 画面：首次向该地址提币加验证或延迟地址白名单

**[7.4]** 第四步提币。这是资产离开交易所的唯一出口，链上转账不可撤回，所以这一层最严。单笔限额、24小时累计、黑名单、KYT 评分，都放在这里。

> 画面：单笔限额 · 24h 累计地址黑名单链上 KYT 评分

**[7.5]** KYT 是链上交易监测。服务商给地址打标签，比如混币器、被盗资金、制裁实体。充值方向命中，就冻结并转合规审核。提币方向命中，就直接拒绝。

> 画面：KYT 标签：暗网市场 · 混币器 · 被盗资金 · 制裁实体 → 充值命中：冻结转合规 提币命中：拒绝

## 场景 8：决策流

**画面标题**：决策流：规则引擎、评分模型、人工审核（逐步动画）

**[8.0]** 现在把各层串起来，看一个风控事件怎样被决策。业界通常用三件套：规则引擎、评分模型、人工审核。

**[8.1]** 第一关是硬规则，比如黑名单、制裁、冷却期。硬规则便宜，可解释，零容忍。示例中这笔提币的目标是制裁地址，直接拒绝，不进模型。

**[8.2]** 没命中硬规则，就计算特征。模型把几十个弱信号，合成一个0到100的风险分。举个示例，这笔分数是18，低于30，直接通过。

**[8.3]** 另一笔分数是52，落在30到70之间。系统要求加验证，比如2FA或邮件确认。加验证是一种软拒绝，它把误杀的成本，转成用户的一次点击。

**[8.4]** 再一笔分数是85，高于70，进入人工审核队列。审核员可以放行，可以拒绝，也可以冻结账户并联系用户。

**[8.5]** 最后，所有决策都要记录，连同当时的特征快照。审核员的结论，就是模型的训练标签。没有记录，模型就无法改进。

> 画面：所有决策 + 特征快照 → 审计日志 → 审核结论 = 模型训练标签

## 场景 9：同步与异步的延迟预算

**画面标题**：延迟预算：同步路径只放便宜的检查（逐步动画）

**[9.0]** 每个风控检查都消耗时间。请求路径上的时间有上限，这个上限叫延迟预算。横轴是对数刻度，下面的数字都是示例。

**[9.1]** 下单的预算不到1毫秒。只能做内存里的检查：余额、价格带、限频计数。调用外部 KYT，或者跑大模型，都来不及。

**[9.2]** 登录宽一些，大约100到300毫秒。可以查设备指纹和 IP 信誉，再跑一个轻量模型。

**[9.3]** 提币可以是秒级到小时级。KYT、复杂模型、人工审核都能用上。链上不可撤回，多等几分钟换安全，是值得的。

**[9.4]** 市场监察是异步的，分钟级到天级。客户端拿到下单回执时，它还没开始。等它发现问题，成交早已发生，只能限制账户、冻结资金、追责。

## 场景 10：令牌桶限流

**画面标题**：令牌桶：允许突发，限制长期速率（逐步动画）

**[10.0]** 网关上最便宜的检查是限流。业界常用令牌桶来讲原理。一个桶最多装B个令牌，系统按速率R往桶里加。示例中，B是10，R是每秒2个。

**[10.1]** 每个请求要取走N个令牌，N就是请求的权重。示例中权重是2。来一个请求，桶里剩8个。

**[10.2]** 令牌桶允许突发。客户端一口气发了5个请求，正好把10个令牌用光。

**[10.3]** 第6个请求来了，桶里一个令牌也没有。系统拒绝请求，返回 HTTP 429。

**[10.4]** 等3秒，按每秒2个补回6个令牌，又能发3个请求。长期来看，平均速率被R锁住，突发大小被B锁住。

**[10.5]** 你可以把它想成一个匀速滴水的杯子，满了就溢出。但比喻不等于实现。币安文档没有说明内部用令牌桶还是固定窗口，令牌桶只是业界通用的解释方式。

## 场景 11：币安 API 权重与 429、418

**画面标题**：按 IP 计权重：429 要停，否则 418（逐步动画）

**[11.0]** 现在对照币安的公开规则。根据币安 API 文档，每个接口有一个权重。重的接口，比如一次查询全部交易对，权重就高。

**[11.1]** 限额按 IP 计算，不按 API Key 计算。每个响应都带一个已用权重的响应头，客户端随时能看到自己用了多少。下单还有独立的订单数限制。

> 画面：按 IP 计算，不按 API Key下单另有订单数限制 X-MBX-ORDER-COUNT-*

**[11.2]** 已用权重超过限额，接口返回429。响应带一个 Retry-After 头，告诉你要等多久。

**[11.3]** 收到429还继续请求，IP 会被自动封禁，接口返回418。

**[11.4]** 封禁时长按违规历史递增，从2分钟到3天。注意封的是 IP，同一 IP 下的全部程序都会受影响。

**[11.5]** 所以客户端要读响应头控制节奏。收到429立刻停下，按 Retry-After 等待。

## 场景 12：误杀与漏放

**画面标题**：阈值一动，误杀和漏放此消彼长（逐步动画）

**[12.0]** 风控本质上是一个分类问题。每个事件有真实标签，好人或坏人，也有风控决策，拦或放。拦了好人，叫误杀。放了坏人，叫漏放。

**[12.1]** 来看一组示例数据。横轴是风险分，绿色是1000个好人，红色是100个坏人，两堆有重叠。阈值放在70，分数达到70就拦。误杀率3.5%，漏放率却有40%。

**[12.2]** 把阈值收紧到50。漏放率降到18%，误杀率涨到12%。

**[12.3]** 再收紧到30。漏放只剩5%，可误杀涨到32%。差不多三个好人里，就有一个被拦。

**[12.4]** 同一个阈值，同时影响误杀和漏放，两者不能同时降到零。人工审核是缓冲区，但容量有限。正常用户等6小时才提到币，体验和被误杀差不多。

**[12.5]** 所以阈值是商业决策：一次漏放的损失，对比一次误杀的损失乘以误杀次数。业界通常让新规则先跑影子模式，只记录不拦截，确认误杀率再上线。

## 场景 13：制裁合规与失败即关闭

**画面标题**：两个必须“硬”的地方

**[13.0]** 最后看两个必须硬起来的地方。第一是制裁合规。主要名单有美国财政部 OFAC 的 SDN 名单，还有联合国、欧盟、英国的名单。

> 画面：制裁名单OFAC SDN · 联合国 · 欧盟 · 英国

**[13.1]** 制裁检查在三处执行。注册和 KYC 时，筛查姓名、国籍和居住地。登录时，筛查 IP 地理位置。充值和提币时，筛查链上地址。

> 画面：① 注册与 KYC：姓名、国籍、居住地② 登录：IP 地理位置③ 充值与提币：链上地址

**[13.2]** 制裁命中是硬规则，直接拒绝并上报合规团队，不能交给模型打分后放行。公开报道显示，2023年币安与美国监管和解，同意支付约43亿美元。合规不是可选功能。

> 画面：命中 = 硬规则，直接拒绝并上报2023 和解：约 43 亿美元 · 公开报道

**[13.3]** 第二是故障时的选择。风控服务宕机了，是放行还是拒绝？资金相关的检查，一律失败即关闭，也就是故障时拒绝。KYT 服务商超时，就转人工，不能默认放行。

> 画面：故障时怎么办资金相关检查：Fail-Closed风控宕机 → 下单拒绝，提币暂停排队KYT 超时 → 转人工，不默认放行

**[13.4]** 再说一个常见误区，以为攻击者会一次提走大额。实际上，攻击者会探测阈值，把提币拆成多笔小额。所以要加24小时累计限额，并且按账户和设备两个维度累计。

> 画面：误区：攻击者会一次提大额实际会探测阈值，拆成多笔小额→ 24h 累计限额，按账户和设备两个维度

## 场景 14：小结与下集预告
