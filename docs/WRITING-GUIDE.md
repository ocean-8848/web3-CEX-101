# 写作规范（ASD-STE100 中文化，80% 遵循）

本规范约束 `docs/learning/` 下的全部文档。目标：读者一次读懂，不需要回读。

## 1. 为什么用 ASD-STE100

ASD-STE100（Simplified Technical English）是航空维修手册的受控语言标准。它的核心是：**一个句子只说一件事，一个词只有一个意思**。我们把它的规则迁移到中文，80% 的内容严格遵循；剩余 20% 留给比喻、故事和案例，让内容生动。

## 2. 规则（严格部分，约 80%）

| 编号 | 规则 | 正例 | 反例 |
|---|---|---|---|
| R1 | 一句话只表达一个动作或一个事实 | 撮合引擎读取订单。它把订单放进订单簿。 | 撮合引擎在读取订单之后会根据价格和时间把它放进订单簿并同时推送行情。 |
| R2 | 操作步骤句 ≤ 20 字；描述句 ≤ 30 字（中文字符，不含术语英文） | 系统冻结 100 USDT。 | — |
| R3 | 用主动语态，主语明确 | 风控服务拒绝该订单。 | 该订单被拒绝了。 |
| R4 | 步骤用编号列表，一步一个动作 | 1. 校验签名。 2. 检查余额。 | 校验签名并检查余额。 |
| R5 | 一个术语只用一个词，全文一致 | 始终写"冻结"，不混用"锁定/占用/扣押" | — |
| R6 | 首次出现的术语给出英文和一句定义 | 吃单方（Taker）：立即与已有挂单成交的一方。 | — |
| R7 | 不用模糊词：大概、一些、相关、等等、可能会 | 确认数达到 12 后，系统入账。 | 确认数差不多够了就会入账。 |
| R8 | 条件写在前，结果写在后 | 如果保证金率低于 1%，系统强平仓位。 | 系统会强平仓位，当保证金率低于 1% 时。 |
| R9 | 警告和注意使用固定标记 | `> ⚠️ 警告：` 会造成资金损失的事项；`> 💡 注意：` 容易误解的事项 | — |
| R10 | 数字带单位；示例数值标注"示例" | 手续费率 0.1%（示例） | 手续费很低 |

## 3. 生动部分（约 20%）

以下内容可以放宽句长和句式：

- **比喻**：用生活场景解释机制。每章至少 1 个。格式：`> 🎯 打个比方：……`
- **案例**：真实事件（例如 2019 年币安被盗、2022 年 FTX 倒闭）。注明年份和公开来源类型。
- **思考题**：每章末尾 2–3 个问题，引导读者用交互页验证。

## 4. 图表规则

- 关系复杂的内容（架构、调用链、状态机、因果）**必须**用 Mermaid 图，不能只用文字。
- 每张图后面写 2–4 行"读图要点"：数据从哪里来、到哪里去、哪里会出错、局限是什么。
- 状态机用 `stateDiagram-v2`；调用链用 `sequenceDiagram`；架构用 `flowchart`；因果用 `flowchart LR`。
- 参数会变化的内容（价格、杠杆、确认数、手续费等级）**必须**链接到 `interactive/` 下的 HTML 页面。

## 5. 事实规则

- 涉及币安的具体数字（费率、等级门槛、确认数），写"截至 2026 年公开资料"或"示例"。币安会调整参数，读者应以官网为准。
- 不知道的内部实现，写"业界通用做法"，不写成"币安就是这样做的"。
- 区分三层：**币安公开的事实** / **业界通用做法** / **本仓库（CEX Demo）的实现**。

## 6. 每章结构模板

```markdown
# NN 标题

> 学习目标：读完本章，你能……（3 条以内）
> 前置章节：……
> 交互实验：[xxx.html](interactive/xxx.html)

## 1. 一句话理解
## 2. 业务视角：它解决什么问题
## 3. 系统视角：它如何实现（图 + 步骤）
## 4. 币安怎么做（公开事实 + 业界做法）
## 5. 故障与边界：哪里会出错，局限在哪
## 6. 本仓库对照（CEX Demo 中的对应服务）
## 7. 术语表
## 8. 思考题
```

## 7. 产品深潜模板（products/P*.md）

每篇覆盖一组产品。对**每个产品**使用同一张"底层逻辑卡"：

```markdown
# PNN 标题

> 学习目标 / 前置章节（链接 ../NN-xxx.md）/ 交互实验（链接 ../interactive/xxx.html）
> ⚠️ 本章不构成投资建议（理财、杠杆、期权类必须写）

## 0. 一句话理解 + 🎯 打个比方

## N. 产品名
### N.1 用户看到什么        （界面、规则、参数；币安公开事实标注"截至 2026 年公开资料"）
### N.2 资金流              （flowchart：谁的钱 → 哪个账户 → 去哪里）
### N.3 状态机              （stateDiagram-v2）
### N.4 系统组件与调用链    （sequenceDiagram，服务名与主线 02 章一致）
### N.5 定价与收益来源      （平台怎么赚钱；用户收益从哪来；给出公式和一个数值示例）
### N.6 风险与对冲          （平台承担什么风险；如何兜底）
### N.7 失败场景与案例

## 末尾：与主线章节的依赖（表格）/ 术语表 / 思考题
```

## 8. 幕后篇模板（backstage/B*.md）

```markdown
# BNN 标题

> 学习目标 / 前置章节 / 交互实验

## 1. 一句话理解 + 🎯 打个比方
## 2. 威胁 / 问题模型        （要防什么：攻击者、错误来源、监管要求；表格）
## 3. 防线分层               （flowchart：纵深防御，每层拦截什么、漏过什么）
## 4. 关键流程               （sequenceDiagram / stateDiagram）
## 5. 规则、指标与阈值       （示例规则表；监控指标；告警条件）
## 6. 真实案例               （年份 + 公开来源类型；因果 flowchart）
## 7. 局限与权衡             （误杀 vs 漏放、成本 vs 安全、体验 vs 合规）
## 8. 本仓库对照
## 9. 术语表 / 思考题
```
